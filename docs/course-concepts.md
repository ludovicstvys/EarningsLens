# Mapping to *Introduction to AI for Business* concepts

This document shows where each course concept is applied in the EarningsLens codebase, with concrete file references so the connection between theory and code is auditable.

| # | Course concept | How EarningsLens applies it | Where in the code |
|---|---|---|---|
| 1 | **Choosing a model that fits the domain** | General-purpose sentiment classifiers misread financial language (e.g. *"flat margins"* is neutral, not negative). EarningsLens uses **FinBERT**, a BERT model fine-tuned on financial news, for the prepared-vs-Q&A tone gap. | `earningslens/sentiment.py` (`_get_finbert`) |
| 2 | **Rule-based vs ML — pick the right tool** | Transcript parsing, hedging detection and risk-vocabulary tracking are deterministic (regex + curated lexicons) because the signal is fully observable and audit-friendly. Topic extraction and Q&A scoring use ML where rules would be brittle. | `parser.py`, `hedging.py`, `risk_vocab.py` vs `topics.py`, `evasion.py` |
| 3 | **Embeddings and semantic similarity** | Quarter-over-quarter topic drift is measured by mean-pooled MiniLM sentence embeddings and cosine similarity between the two prepared-remarks vectors. | `earningslens/topics.py` (`_mean_embedding`, `_cosine_similarity`) |
| 4 | **Prompt engineering — structured outputs** | The Q&A evasion prompt forces the model to emit exactly two lines (`SCORE: <int>` and `WHY: <sentence>`), and a regex parser refuses any other shape. This converts a generative model into a reliable scoring function. | `earningslens/prompts.py` (`EVASION_SCORING_PROMPT`); `earningslens/evasion.py` (`_parse_score_response`) |
| 5 | **LLM-as-judge (Zheng et al., 2023)** | Each analyst-question / executive-answer pair is scored by a small instruct LLM acting as a rubric judge. The rubric is constrained, the score is clamped to 0–10, and the model never sees one pair while scoring another. | `earningslens/evasion.py` (`_score_pair_with_llm`, batched in `_score_pairs`) |
| 6 | **Evaluation and guard-rails for generative output** | The LLM's response goes through three quality gates before being trusted: echo detection (overlap with the answer), placeholder detection (template fragments), and "claimed-not-asked" detection (model hallucinates that the question was absent). Failing any gate replaces the model output with deterministic reasoning. | `earningslens/evasion.py` (`_looks_like_echo`, `_looks_like_invalid_reasoning`, `_looks_like_missing_question_claim`, `_adjust_score`) |
| 7 | **Deterministic backup paths** | When the LLM returns an unparseable response or a low-confidence pair, a non-ML heuristic still produces a score with full provenance tagging (`source="heuristic_fallback"`, `"fallback_extract"`, `"fallback_summary"`). Users always know whether they are reading a model-generated or rule-generated result. | `earningslens/evasion.py`, `earningslens/topics.py` (`_fallback_themes`), `earningslens/synthesizer.py` (`_build_fallback_summary`) |
| 8 | **Local inference vs cloud APIs** | Every model runs on the user's machine via Hugging Face's `transformers` and `sentence-transformers`. No transcript text leaves the device. This is a deliberate design choice for confidentiality in finance use cases. | `earningslens/local_llm.py`, `earningslens/config.py` (model paths default to a local cache) |
| 9 | **Cost / latency / quality tradeoffs** | The default local LLM is `HuggingFaceTB/SmolLM2-1.7B-Instruct` — a deliberate downshift from 7B+ models so the app runs on 8 GB Macs. Performance is recovered with batched generation (`EVASION_BATCH_SIZE`), `max_new_tokens=64`, and deferred MPS cache clearing. | `earningslens/local_llm.py` (`generate_text_batch`), `earningslens/config.py` (`EVASION_BATCH_SIZE`, `LOW_MEMORY_MODE`) |
| 10 | **Responsible AI / human-in-the-loop** | Every screen carries a disclaimer: outputs are analytical aids, not investment advice. Low responsiveness scores are explicitly framed as *prompts for a human to re-read the exchange*, not as evidence of misconduct. | `app.py` (banner + signal copy); `docs/user_guide.md` and `EarningsLens_User_Guide.pdf` (closing section) |
| 11 | **Bias awareness** | The hedging and risk vocabularies were authored with finance-domain bias in mind (terms a CFO might use defensively differ from those in legal or scientific text). Sources are cited in `README.md`. | `earningslens/hedging.py`, `earningslens/risk_vocab.py`, `earningslens/vocab.py` |
| 12 | **Reproducibility as an engineering discipline** | Pinned Python version, `requirements.txt`, `.env.example`, deterministic sample transcripts, one-click launchers (`launch.command`, `launch.bat`), a regression test suite (`pytest`), a `health_check.py` script, and an `architecture.md` so reviewers can trace any output back to its inputs. | repo root + `scripts/` + `tests/` |
| 13 | **Provenance and observability** | Every analysis attaches a `source` field (e.g. `"finbert"`, `"model"`, `"heuristic_fallback"`, `"fallback_extract"`) and the Streamlit UI surfaces these as badges. Reviewers can tell at a glance which numbers came from which path. | `earningslens/models.py` (dataclass fields), `app.py` (provenance rendering) |
| 14 | **Error surfacing over silent fallbacks** | If an analysis raises an exception, EarningsLens halts the run and shows the exception verbatim rather than substituting `flagged=False` defaults that would falsely signal "all clear". | `app.py` (`record_analysis_failure`, terminal `st.error` + `st.stop()` block) |
| 15 | **Concise synthesis of multi-signal outputs** | The final analyst brief is generated by the local LLM **from the structured outputs only** — not from the raw transcript — so it is anchored to explicit evidence and unable to hallucinate quotes. | `earningslens/synthesizer.py` (`SYNTHESIS_PROMPT`) |

## How to read this table

Each row in this table is something a course lecture or reading covered, then mapped to the file and function where that idea is implemented. Reviewers can use the right-hand column as direct entry points into the code if they want to verify how a particular concept was applied.
